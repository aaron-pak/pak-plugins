How the top-rated movies query works, line by line

It joins two tables, throws out movies too few people rated, and sorts what's left. Point at a note to light up its line.

The question

Which movies do people rate highest, if enough of them voted?

The ratings live in one table and the titles in another. A movie with three perfect votes shouldn't beat one with forty thousand very good ones, so the query needs a floor on the number of votes.

The query

Four steps in eleven lines

-- Top-rated movies with enough votes to trust
SELECT b.primary_title, b.start_year,
       ROUND(r.average_rating, 1) AS rating,
       r.num_votes
FROM title_basics AS b
JOIN title_ratings AS r ON r.tconst = b.tconst
WHERE b.title_type = 'movie' AND r.num_votes >= 25000
ORDER BY
  rating DESC,
  r.num_votes DESC
LIMIT 5;

A common mistake

Filtering after you sort does nothing

The first version on the class forum put the vote floor in the wrong place. The fix moves it into WHERE.

 FROM title_basics AS b
 JOIN title_ratings AS r ON r.tconst = b.tconst
-WHERE b.title_type = 'movie'
+WHERE b.title_type = 'movie' AND r.num_votes >= 25000
 ORDER BY rating DESC
-LIMIT 5;  -- then drop small ones by hand
+LIMIT 5;

Rule of thumb

Anything that decides which rows count goes in WHERE. ORDER BY and LIMIT only decide which of the counted rows you see.
